# Моделирование очереди в магазине

Тема лабораторной: **«Исследование влияния числа касс на время ожидания покупателей методом стохастического моделирования»**.

Цель — определить минимальное число касс из 1, 2 и 3, при котором среднее время ожидания покупателя не превышает 5 минут при заданном потоке покупателей.

## Постановка задачи

Магазин работает 8 часов. Покупатели поступают по пуассоновскому потоку с интенсивностью 20 человек в час: независимые интервалы между приходами имеют экспоненциальное распределение со средним 3 минуты. Время обслуживания также имеет экспоненциальное распределение со средним 2 минуты. Приходы и обслуживание независимы. Это условные параметры учебной модели, а не измеренные данные магазина.

У каждой кассы своя неограниченная очередь. При приходе покупатель выбирает кассу с наименьшим числом людей, включая того, кого сейчас обслуживают. При равенстве выбор равновероятный. Покупатель не знает будущих времён обслуживания и после выбора не переходит в другую очередь. В каждой очереди обслуживание идёт в порядке прихода, а разные кассы работают параллельно. Кассы одинаковые, работают без перерывов. Покупатели не уходят из очереди. В начале дня магазин пуст. После закрытия новые покупатели не приходят, но все уже пришедшие получают обслуживание. Время ожидания отсчитывается до начала обслуживания и не включает само обслуживание.

Модель представляет собой систему массового обслуживания с несколькими кассами и выбором самой короткой очереди. Пуассоновский входной поток распределяется между очередями по их текущему состоянию. Обычные формулы M/M/c с общей очередью к этой схеме напрямую неприменимы. Исследуется конечный рабочий день с пустыми начальными очередями. Начальный период включён в результаты, поскольку открытие магазина является частью постановки.

## Исследовательский вопрос и гипотеза

Вопрос: сколько касс необходимо, чтобы среднее время ожидания не превышало 5 минут?

Гипотеза: увеличение числа касс снижает ожидание и долю покупателей, ожидающих дольше 5 минут, но уменьшает среднюю загрузку каждой кассы. Исходная проверяемая гипотеза — для выбранного потока достаточно одной кассы.

## План эксперимента

1. Сравнить 1, 2 и 3 кассы при одинаковых параметрах спроса и обслуживания.
2. Для каждого варианта выполнить 200 независимых моделирований восьмичасового дня.
3. Сравнить среднее время ожидания, долю ожиданий больше 5 минут и загрузку касс.
4. Построить графики и определить минимальное достаточное число касс.

В пределах одного моделируемого дня все варианты получают одинаковые моменты прихода и времена обслуживания покупателей. Это делает сравнение более точным. Разные дни генерируются независимо. Начальное значение генератора фиксируется для воспроизводимости. Для случайного выбора между равными очередями используется отдельный генератор для каждого дня и числа касс. Поэтому добавление нового варианта числа касс не меняет результаты остальных вариантов и входной поток.

Программа использует событийный подход: к моменту прихода покупателя удаляет из очередей уже обслуженных людей, выбирает самую короткую очередь и вычисляет начало обслуживания по времени освобождения выбранной кассы после всех людей перед ним. Завершение обслуживания точно в момент прихода учитывается до выбора очереди. Перебирать небольшие шаги времени не требуется.

Среднее ожидание и доля долгих ожиданий сначала рассчитываются отдельно за каждый день, затем усредняются по дням. Тем самым оцениваются показатели типичного рабочего дня; они могут немного отличаться от усреднения по всем покупателям сразу. Для среднего ожидания строится приближённый 95% доверительный интервал: среднее дневных значений ± 1,96 × выборочное СКО дневных значений / √число дней. Для сравнения с порогом полезно проверять и верхнюю границу этого интервала. Интервал характеризует точность оценки среднего, а не диапазон ожидания отдельных покупателей.

Загрузка — суммарное время занятости касс в пределах восьмичасового дня, делённое на число касс и продолжительность дня. Обслуживание после закрытия учитывается в ожидании покупателей и отдельно в длительности переработки.

## Запуск

Проверено на Python 3.14. Зависимости NumPy и Matplotlib с фиксированными версиями перечислены в `requirements.txt`. Остальные используемые модули входят в стандартную библиотеку Python.

Создание виртуальной среды и установка зависимостей в PowerShell из папки проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe simulation.py
```

Эти команды не требуют активации среды. Если удобнее работать с активированной средой:

```powershell
.\.venv\Scripts\Activate.ps1
python simulation.py
deactivate
```

Если PowerShell запрещает выполнение `Activate.ps1`, используйте прямой вызов Python из `.venv`, как в первом примере.

Параметры можно менять, например для исследования повышенного спроса:

```powershell
.\.venv\Scripts\python.exe simulation.py --arrival-rate 28 --runs 500 --output results_high_demand
```

Результаты по умолчанию сохраняются в `results`: сводная таблица `summary.csv`, данные отдельных дней `daily_results.csv`, параметры `parameters.json`, графики `comparison.png`.

## Ввод исходных данных

Пошаговый ввод всех параметров:

```powershell
.\.venv\Scripts\python.exe simulation.py --interactive
```

Enter сохраняет значение в скобках. Для дробных чисел допустимы точка и запятая. Число касс вводится через пробел, например `1 2 4`. При ошибке программа предложит повторить ввод.

Для повторяемых экспериментов редактируйте `config.json`:

```powershell
.\.venv\Scripts\python.exe simulation.py --config config.json
```

| Ключ JSON | Аргумент | Значение |
| --- | --- | --- |
| `arrival_rate` | `--arrival-rate` | Поток, покупателей в час, > 0 |
| `service_mean` | `--service-mean` | Среднее обслуживание, минут, > 0 |
| `hours` | `--hours` | Продолжительность дня, часов, > 0 |
| `cashiers` | `--cashiers` | Список положительных целых чисел |
| `runs` | `--runs` | Количество моделируемых дней, целое ≥ 2 |
| `threshold` | `--threshold` | Порог ожидания, минут, > 0 |
| `seed` | `--seed` | Начальное значение генератора, целое ≥ 0 |
| `output` | `--output` | Папка результатов |

В JSON дробные числа записываются с точкой, число касс — списком, например `[1, 2, 4]`. Можно указать только часть параметров. Неизвестные ключи и некорректные значения вызывают ошибку. Повторяющиеся варианты числа касс объединяются, список сортируется.

Порядок применения настроек: стандартные значения, затем JSON, затем аргументы командной строки, затем изменения при интерактивном вводе. `config.json` читается только при явном указании `--config`.

Пример переопределения потока и числа касс:

```powershell
.\.venv\Scripts\python.exe simulation.py --config config.json --arrival-rate 35 --cashiers 2 4 --output results_busy
```

Относительный путь `output` в JSON отсчитывается от папки файла настроек. Путь из командной строки или интерактивного ввода — от текущей папки терминала. Каждый запуск сохраняет итоговые настройки в `parameters.json`; его можно передать в `--config` для повторения эксперимента. При сохранении в ту же папку результаты перезаписываются.

Исходные значения 20 покупателей в час, 2 минуты обслуживания, 8 часов работы, 200 дней и кассы `[1, 2, 3]` остаются базовым сценарием исследования. Новые сценарии можно задавать без изменения исходного кода.

В репозиторий входят исходный код, тесты, `config.json`, `README.md`, `requirements.txt` и `.gitignore`. `.gitignore` исключает исходные лекции из папки `Материалы`, виртуальную среду, кэш Python, локальные настройки и генерируемые папки `results` и `results_*`. Эти файлы остаются на компьютере, но не попадают в коммиты. После клонирования проекта виртуальная среда создаётся заново по инструкции выше.

## Границы выводов

Результат относится к указанным распределениям, постоянному потоку покупателей и отдельным очередям с выбором самой короткой. Реальные пики спроса, перерывы, переходы между очередями и отказы от ожидания здесь не рассматриваются. Среднее ожидание меньше 5 минут не означает, что каждый покупатель ждёт меньше 5 минут, поэтому доля долгих ожиданий выводится отдельно.

Если потребуется расширить исследование, можно при тех же правилах менять интенсивность прихода покупателей и искать, при какой нагрузке одной кассы становится недостаточно.
